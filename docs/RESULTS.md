# Results — operational baselines

> Generated by the pipeline; the authoritative per-question data lives in `results/<track>/phaseN/`
> (gitignored). This page records the protocol each number belongs to. Mini tracks are plumbing
> checks: their corpora are tiny and evidence is shared, so **do not** compare Phase 1 vs Phase 2,
> or mini vs full, on them.

## Protocol

| | |
|---|---|
| Chunking | 256 / 32 tokens (all MetaQA phases) |
| Retrieval depth | `top_k = 20` |
| Shared prompt | sha256 `5de2288e17855119b17760d9b5d33689e05c0e8c1f8329288513ec2d0a4b98fa` |
| Generation / judge | `gpt-5.6-luna` (temperature 1 — the only value gpt-5-family models accept) |
| Extraction (Phase 2) | `gpt-5-mini` (temperature 1) |
| RAGAS | `gpt-4o-mini` (RAGAS injects `temperature=1e-8`, unsupported by gpt-5-family) |
| Embeddings | `text-embedding-3-small` |
| Runs | every run writes `run_meta.json` (eval/corpus hashes, chunking, top_k, models, temperatures, prompt/ontology hashes); a resume with a different fingerprint is refused |

Every run below completed with **0 `Error:` rows and 0 empty contexts**. Closed book has no
RAGAS (no contexts by design).

On mini30 the ablation is clearer: baseline gold recall 0.739 / evidence 0.892 / judge 0.867
vs no-neighbours 0.681 / 0.792 / 0.833 (30/30 answered, 0 errors). The 1-hop neighbour chunks
are doing real work, not decoration.

`results/metaqa_mini/phase2_no_neighbours/`; it is never the baseline.

## Operational facts

- Phase 1 ingest is deterministic: `hotpot-qa_metaqa` rebuilt to exactly **4,522 chunks**.
- Phase 2 ingest records `errors`, `policy_skips`, `retries`, token counts and wall clock in
  `ingest_meta.json`; a content-policy rejection is a per-chunk skip (chunk keeps its text and
  embedding), never a hard failure.
- Phase 3a always uses `*-ontology-graph`, never the Phase 2 database, and records the ontology
  sha256 (`461f37ed…`) in `run_meta.json`.
